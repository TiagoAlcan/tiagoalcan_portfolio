<CaseStudy.Context>

Quando cada ambiente recebe a aplicação de um jeito, as diferenças aparecem na pior hora: o que funcionou em um lugar falha em outro, e ninguém sabe dizer qual versão está rodando onde.

</CaseStudy.Context>

<CaseStudy.Process>

<CaseStudy.Step title="O que vai para o ar fica no Git">
O que define um deploy passou a ser versionado. Com histórico, dá para saber o que mudou, quando e por quê.
</CaseStudy.Step>

<CaseStudy.Step title="Uma imagem, uma versão">
As aplicações passaram a ser publicadas como imagens no Docker Hub. O ambiente deixa de montar a aplicação e passa a <Mark>baixar a mesma imagem que os outros</Mark>.
</CaseStudy.Step>

<Terminal title="exemplo fictício" lines={["$ docker pull empresa/aplicacao:1.4.2", "$ docker run -d --name aplicacao empresa/aplicacao:1.4.2"]} />

</CaseStudy.Process>

<CaseStudy.Result>

Os deploys ficaram padronizados e versionados, com menos inconsistência entre ambientes. Os nomes de aplicações, imagens e servidores são confidenciais; o comando acima é só um exemplo do formato.

</CaseStudy.Result>
